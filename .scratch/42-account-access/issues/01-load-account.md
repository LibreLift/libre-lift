# Task: Load application Users after verification with account-loading retry

Published: https://github.com/open-source-fitness/open-fit/issues/108

**Goal**: A returning user enters training with their stored application account name and can recover from account-loading failure without another code.

**Context**: Part of #107, the completion specification for #42. Supports M1: Runnable Demo. Implementation: agent. Approved scope and testing seams. Unblocked; eligible for Ready.

## What to build

After successful email-code verification, load the authenticated account's application User through the service, ViewModel, and guarded UI. A named User opens Templates; a confirmed absent User opens the existing name-onboarding screen. Loading errors show Retry loading account, which repeats only the User lookup using verified authentication retained in memory.

- [ ] Pending retries prevent duplicate/conflicting actions; appearance Settings remains reachable.
- [ ] Current-run state and navigation distinguish verified authentication from unresolved application account data; cross-launch restoration remains #43.
- [ ] Existing router tests cover the complete loading/failure/retry/navigation path and existing OTP regressions stay green.
- [ ] Real local Supabase checks prove an existing application User is loaded and a missing User remains absent after verification; documentation covers recovery and the new read contract.
- [ ] TypeScript, Jest, and relevant native bundling/dependency checks pass.
