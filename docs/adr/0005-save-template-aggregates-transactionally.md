# Save whole templates transactionally in the requesting user's context

For #45, retain the service → HTTP handler/Edge Function → data access → database boundaries and perform a whole-template save in a narrowly scoped transactional database function with invoker rights and the requesting user's credentials. Separate row requests cannot atomically update metadata, placement membership/order, snapshots, and sets; accepting a database function and additive migration keeps partial writes from escaping while preserving #102's row-level ownership policies. Commit successful-save retry recognition in the same transaction so a lost response can be retried without duplicate creation or overwriting a later save; ordinary application operations never use privileged service credentials.
